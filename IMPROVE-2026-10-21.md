# Improvement Deep-Dive — indexstr-v3 — 2026-10-21

Scope: distributed indexing network (intake of network kind 39697 events, local SQLite index, heartbeats). Files read: `package.json`, `src/crawler/index.ts`, `src/crawler/internal/modules/intake.ts`, `src/crawler/internal/` + `src/protocol/webIndex.ts`, `.github/workflows/`, `AUDIT-2026-10-21.md` (existing security audit — confirms signature verification is currently delegated entirely to the Nostr layer).

## Top recommendations (ranked, with effort S/M/L)

1. **Design the signature-verification enforcement point before intake ships (S/M).** `src/crawler/internal/modules/intake.ts` currently validates structure, freshness, SSRF, crawl-traps, and per-indexer caps — but never verifies the Schnorr signature, and never re-checks the `d ↔ u` binding (`documentId(normalizeIndexUrl(u)) === d`). Recommended enforcement design:
   - **Point:** inside `NetworkIntake.poll()`, immediately after structural sanity and *before* rate/cap accounting (so forged events can't consume another pubkey's budget).
   - **Order of checks (cheap → expensive):** dedupe by event `id` → structural parse → `created_at` freshness (already present) → `verifyEvent(event)` from `nostr-tools` (sync schnorr verify, ~1 ms; fine at 250 events/poll) → `d`↔`u` hash rebinding.
   - **Failure handling:** new `DropReason` values (`bad-sig`, `d-mismatch`), counted separately in telemetry so a relay feeding garbage is distinguishable from organic spam; consider per-source-relay quality scoring later.
   - **Why not "trust the relay":** relays *should* verify, but intake hears multiple relays and future non-relay transports; defense-in-depth at the boundary is cheap and makes per-pubkey reputation/caps meaningful (caps are trivially bypassed by key rotation — that needs WoT/stake later, but sig checks are the prerequisite for any pubkey-attributed policy).
   - **Cache:** LRU on verified event ids so re-broadcasts (a known griefing vector noted in the audit) don't re-verify.
2. **PR CI + branch protection (S).** No PR-triggered workflow; `main` unprotected. The intake module is config-flagged off by default — exactly the kind of code that rots without a test gate. Add `vitest run` + `tsc --noEmit` on PRs, then require it.
3. **Kill the vendored `@sip01/protocol` alias (M).** `package.json`/tsconfig alias `@sip01/protocol` to a local `sip-01-core/` copy; Crawlstr-v3 and 0xSearchstr carry their own copies of the same files (sizes already diverge). Publish one versioned package keyed to the spec version (see SIP-01 report).
4. **Dep refresh (S)** — table below.

## Missing gates (CI/tests/protection)

- No PR CI, no branch protection, no required reviews (org-wide pattern).
- Deploy workflow uses `npm install` not `npm ci`.
- No test coverage gate around `intake.ts` despite it being the network trust boundary — add adversarial fixtures (forged sig, d-mismatch, replayed id, future created_at) before enabling intake in production.
